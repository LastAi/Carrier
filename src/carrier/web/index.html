Projects

Ready Room

Set your projects up here before you fly. Each project has a long-term goal (what the project is), rules, and a queue of tasks — the current one is what Flight Deck works on.

  • Global rules apply to every session; project rules add to them.
  • Rule sets are reusable bundles of rules you can attach anywhere.
  • Session presets save a model, permission mode and overlap setting.
  • Project templates are starting points for new projects.
  • Tags help you find projects; they're only for you and never sent to Claude.

            Routines — repeatable tasks

            A routine is a task the project runs again and again — update the docs after each task, push to GitHub once everything is reviewed. Run puts it next in the queue; "after each task" routines queue themselves when a task is finished. A routine that needs a clear review can only start when nothing is waiting in Debrief.

            Flight Deck

            Work happens here: start a project's current task, guide Claude Code as it works, stop it, and mark the task done. Several sessions can run at once; sessions in linked projects are kept aware of each other.

            • Projects, their goals, rules and task queues are set up in the Ready Room.
            • A standalone task is a one-off with no project. Later you can turn it into a project, or add its finished work to an existing project's history.

            Debrief — review what changed

            Pick a project. Debrief shows every change since its last review — across all of the project's folders — explains why each was made and which task made it, and lets you approve or request fixes. Requested fixes go back to the project as its next task.

              Debrief uses git to see exactly what changed. Tracking takes a snapshot of a folder as it is now; changes after that are reviewable.

              Extra folders are always reviewed since their own last review.

              Scan the whole project instead — no history needed, e.g. a security check

              Every file in the project's folders is checked as it is now by the agents you pick. Scans don't change what counts as reviewed, and fixes you request still become the project's next task.
